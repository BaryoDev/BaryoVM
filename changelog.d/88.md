- **Stacks can deploy from a recipe in the app's own repository.** `baryovm stack add NAME --recipe PATH` (or `stack release NAME --recipe PATH`) reads a versioned `baryovm.recipe.json` and `stack release` brings its services up one at a time, waiting on each `healthUrl`. If a service fails, every service touched so far goes back to the previous compose file; a service the previous recipe did not have is removed. Names, images, ports and paths from a recipe are checked against a strict shape and quoted on every remote command, and a recipe with an unknown `schema` is refused. Inputs are bound with `--input NAME=env:VAR` or `file:PATH`; a secret input takes a reference only and never a default, and `cmd:` is refused. A stack without a recipe releases as before. Not built yet: `files`, `routes`, `backup` and service `build` in a recipe release, `--dry-run`, `--resume`, and a generic `stack domain add`. The barako examples in the help text and code comments are now generic. ([#88])
