- **`baryovm site add <domain> --vm <vm> --root <dir>` and `baryovm site deploy <domain> <dir>` provision and update a static site.** `site add` creates the webroot and the ACME challenge directory, writes an nginx server block from a template (HTTP to HTTPS redirect, TLS, `try_files` for a static export, a year-long cache on hashed assets, `no-cache` on HTML, gzip scoped to the static locations), gets a certificate with certbot in webroot mode, runs `nginx -t` and reloads, and relabels the webroot with `restorecon` where SELinux is on. The order is HTTP-only block, certificate, full block; a failing step puts the previous server block back, and the error and `data.failedStep` name the step. An existing site is refused without `--force`. `site deploy` syncs a directory into the recorded webroot with the same rsync as `stack release`, then runs `nginx -t` and reloads. Sites are recorded in `fleet.json`. DNS is not handled. Tested with fakes through the cobra commands, never against a real VM. ([#18])
